📬 Inbox у Smartico

Практична інструкція: формати, налаштування та специфіка аналітики

Inbox — це внутрішній центр сповіщень сайту (іконка дзвіночка). На відміну від попапу, він з'являється у кутку екрана у вигляді спливаючого тосту, не перериває гру в слотах і залишається у списку повідомлень у віджеті.

Simple Inbox

  • Склад: Іконка + Заголовок + Короткий текст (прев'ю).
  • Клік: Одразу переводить користувача за вказаним лінком без відкриття віджета.
  • Застосування: Короткі тригерні новини на 1 клік («Депозит зараховано», «Нараховано 20 FS»).

Rich Body Inbox

  • Склад: Прев'ю + Повноцінний HTML-опис (банери, правила, умови) + до 2 кнопок дій (CTA).
  • Клік: Розгортає вікно повідомлення у віджеті, де користувач читає умови та обирає кнопку.
  • Застосування: Промо-акції, турніри, депозитні бонуси, де потрібен опис та банер.
  1. Створення: Перейдіть у Marketing → Inbox → New Inbox.
  2. Базові поля (General):
    • Name: Назва шаблону (наприклад: [Trigger] FS_Welcome_Ukr).
    • Message expiration period: Термін життя сповіщення в скриньці (за замовчуванням 30 днів; для тимчасових акцій ставте 7–14 днів).
    • Title: Короткий заголовок (до 40 символів).
    • Short preview for body: Текст прев'ю тосту (до 80 символів).
    • Icon: Квадратне зображення 128×128 px.
  3. Налаштування кнопок дій (CTA) та лінків:
    Увага: Не вставляйте лінки через <a href="..."> всередину Rich HTML! Тіло інбоксу рендериться в ізольованому Sandboxed-фреймі із захистом CSP. Будь-які посилання всередині HTML блокуються браузером і не відкриються. Всі кнопки налаштовуються виключно в окремих полях BackOffice!
    • Для Simple: поле Deep link or URL.
    • Для Rich: поля CTA Primary Button Text + Deep link for Primary Button (та за потреби Secondary).
    Правило посилань: використовуйте ТІЛЬКИ відносні шляхи зі слешем /! Ніколи не пишіть https://whitelabel.com/deposit (це ламає авторизацію при грі на дзеркалах сайту).
    Розділ ❌ Неправильно ✅ Правильно для поля Deep link
    Каса / Депозит https://site.com/deposit /deposit
    Бонуси https://site.com/bonuses /bonuses
    Місії (гейміфікація) — dp:gf_missions
    Турніри (гейміфікація) — dp:gf_tournaments
  4. Тривалість показу тосту на сайті (Custom Data):

    Оскільки віджет інтегровано через API, для збільшення часу показу тосту (щоб він не зникав за 5 сек) у блоці Additional settings знайдіть поле Extra parameters та вставте:

    {"visibility_period_sec":10}
  5. Перемикач прев'ю: Переконайтеся, що чекбокс Show preview of the message for a short period if user is online увімкнено.

Специфіка каналу Inbox у Smartico:

  • На відміну від Email або SMS, для Inbox немає зовнішніх операторів зв'язку, тому окремий статус технічної доставки (Delivered, код 6) для цього каналу не формується.
  • В аналітичних BI-звітах та агрегованій статистиці комунікацій метрика Delivered для інбоксів автоматично прирівнюється до метрики Impression (показ).

Як фіксується доставка та показ (Онлайн vs Офлайн):

  • Збереження (Sent): При спрацьовуванні кроку кампанії повідомлення миттєво записується в базу даних у віджеті Inbox (notification center) користувача зі статусом Sent — це відбувається як для онлайн-, так і для офлайн-гравців.
  • Онлайн-гравці: Спливаюче прев'ю повідомлення (тост) відображається лише тим користувачам, які перебувають онлайн у момент відправки. Саме для них одразу реєструється факт Impression (і в звіт йде Delivered).
  • Офлайн-гравці: Повідомлення залишається в їхній скриньці (якщо в налаштуваннях кроку кампанії вимкнено параметр expire_on_timeout, тобто повідомлення не згорає через таймаут). Статус Impression для них фіксується поступово — в момент, коли користувачі повертаються на сайт і відкривають сторінку або віджет повідомлень.
Де дивитися правильні дані:
  • Sent (Надіслано): показує загальний пул гравців, яким повідомлення було успішно згенеровано і записано в скриньку.
  • Delivered / Impression (Доставлено/Показ): показує реальну кількість гравців, які фізично побачили повідомлення (онлайн у момент пушу + ті офлайн-гравці, які повернулися пізніше).
  • Clicks: фіксує кліки по окремих CTA-кнопках шаблону через системну подію reportClickEvent.
